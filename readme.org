#+TITLE: finances
#+OPTIONS: toc:nil num:nil

Personal finance tool in Emacs Lisp.  ODS spreadsheet is the source of truth; SQLite mirrors it; a dark static HTML dashboard renders reports.

Zero external runtime deps beyond Emacs 29+ stdlib and macOS-bundled =unzip= / =zip= / =open=.  Python 3 only used for one-shot ODS migrations.

* Setup

Two install paths.  Pick either; they coexist.

** Interactive (Emacs)

Drop one line in =init.el=:

#+begin_src elisp
(load "/path/to/finances/bootstrap.el")
#+end_src

=bootstrap.el= self-locates the repo via its own load path, wires =load-path=, and requires =core=.  Move the repo → update one line (or symlink the repo to a stable location once and never touch =init.el= again).

** CLI (batch / cron / scripts)

=bin/finances= is a self-locating shell wrapper.  Link it once:

#+begin_src sh
make install                # symlinks $(PREFIX)/bin/finances -> bin/finances
                            # PREFIX defaults to ~/.local
#+end_src

Then:

#+begin_src sh
finances fin-dashboard      # regenerate HTML, open in browser
finances fin-sync-refresh   # ODS → DB only
finances fin-db-rebuild     # drop + recreate tables
finances --shell            # ielm REPL with code loaded
#+end_src

Uninstall: =make uninstall=.

Schema is auto-created on first =M-x fin-db-rebuild= (or =finances fin-db-rebuild=).

* Daily workflow

1. Open =~/Projects/finances/infra/seeds.ods= in LibreOffice.
2. Add or edit rows (entries / plan / patrimony / accounts).
3. Save.
4. =M-x fin= — refreshes the DB and opens the dashboard in your browser.

* ODS layout

Four sheets.  All category/name values *lowercase kebab-case*; item descriptions keep case + accents.  All monetary values are *integer cents*.

** =entries=
=date | type | category | item | amount | installment | installments=

- =type= ∈ {=in=, =out=}
- CNPJ tax is a normal =type=out= row under =category=cnpj= (positive cents).  It is netted out of gross income in the liquid base (see /Liquid/), not treated as ordinary spend there.
- Every entry is a leaf; aggregations sum all rows of the relevant =type=.  An un-itemized lump just leaves =item= NULL and surfaces under its category in the cashflow drilldown.
- =amount= = cents (integer).
- =installment= / =installments=: whole numbers /k/ of /n/ for a purchase paid in installments, one row per installment; both empty otherwise.  Sync rejects anything but 1 ≤ k ≤ n.

** =plan=
=category | parent | type | amount | share=

- =type= ∈ {=fix=, =var=}
- Fix rows are driven by =amount=; share derived = amount / liquid.
- Var rows are driven by =share=; amount derived = share × liquid.
- Children of a parent (e.g., var children of =investments=) can use either driver.
- =investments= var children = ODS-declared extras (=family=, =vacations=, =emergency=) + auto-derived patrimony amortization per category.

** =patrimony=
=category | item | amount | lifespan_months=

- Monthly amortization derived = =amount / lifespan_months=.

** =accounts=
=category | parent | balance | updated_at=

- Children of a bucket (e.g., =nu=, =bb=, =wanu= under =emergency=) sum into the parent.
- Reserve target = 12 × fix-monthly; runway derived from =SUM(balance WHERE parent='emergency') / fix=.

* Liquid

=monthly_liquid= = AVG over the current year's months of (Σ =type=in= − Σ =category=cnpj=).
CNPJ tax (a =type=out= row under =category=cnpj=) is subtracted from gross income in this base rather than counted as expense.

* Bank reconciliation

The ODS stays canonical; bank statements fix it.  =M-x fin-bank-fix= compares every bank row since =fin-bank-fix-from= (2024-01-01) with the ledger, writes the fixes into the ODS and shows what it did.  Running it again changes nothing.

** Sources (Nubank, free)

- *Account*: app → Extrato → Exportar extrato → OFX.  Any date range.
- *Card*: app → Cartão de crédito → Resumo de faturas → closed bill → Enviar fatura por e-mail → OFX.  One bill per file, sent as an email attachment.
- History older than the app allows: LGPD request to Nubank's DPO (=dponubank.zendesk.com=).

** Monthly flow

1. Export last month's account statement and the closed card bill; copy both into =infra/inbox/=.
2. Close the ODS in LibreOffice: its next save would undo the fix (=fin-bank-fix= refuses while the lock file exists).
3. =M-x fin-bank-import= — renames files to =nubank-<account|card>-<start>_<end>.ofx= from the statement period, removes a re-export of a statement already there, imports new rows into =bank_txn=.  Rows dedup by =FITID= plus date, amount and memo (Nubank reuses a =FITID= across installments and refunds).
4. =M-x fin-bank-fix= — writes the fixes; backup in =infra/backup/=.  =C-u M-x fin-bank-fix= is a dry run.
5. Read /Needs a look/ in the report (salary gaps, refunds with no purchase), fix those by hand if needed.
6. =M-x fin=.

=M-x fin-bank-reconcile= (one year's review buffer) and =M-x fin-bank-copy-missing= (bank-only rows as TSV) remain for reading without writing.

** What a fix does

Before matching, bank rows the ledger never books on their own are folded or dropped:
- a refund cancels its purchase; a partial refund reduces it; a refunded purchase already in the ledger is deleted from it;
- IOF adds to, an installment discount (/Desconto Antecipação/) subtracts from, its purchase;
- a Pix paid with /Pix no Crédito/ counts once, on the card;
- card bill payments, card credit moved to the account and back, cent-level debt adjustments, and transfers between own accounts (=fin-bank-own-regexps=) are ignored;
- savings moves (=fin-conv-savings-regexps=: RDB, crypto, ETF) are skipped: the ledger books savings per goal (=investments= / =retirement= / =reserve=, balances in the =accounts= sheet).

Matching, in order:
- *Exact*: same =type= and =amount=, dates within =fin-reconcile-window= (3 days).
- *Near*: within the window, amount gap ≤ =fin-reconcile-near-ratio= (5%) with a word shared by bank payee and ledger =item= (case and accents ignored), or gap ≤ =fin-reconcile-near-close-ratio= (1%).
- *Shifted*: the ledger date is off: same amount (≤ 1%) within =fin-reconcile-shift-window= (14 days) and the ledger row names the payee; the same installment (bank =Parcela k/n=, ledger =installment= / =installments=, amount ≤ 1%) within =fin-reconcile-exact-window= (31 days), since the ledger names installments after the item and dates the first at purchase; or an exact amount of at least R$100 with cents within 31 days.
- *Combined*: one ledger row booking two bank rows of the same payee.

Then the fix:
- *adds* each bank-only outflow under the category the ledger history books that payee under, else =fin-conv-default-category= (=free=), installments with /k/ and /n/ from the bank's =Parcela k/n= — but only while the month's ledger spending stays within the bank's (categories in =fin-bank-fix-unspent-categories= left out); a month already at the bank's total gets its bank-only rows reported instead, since the ledger books them in its own shape;
- *adds* money received from people under =fin-conv-inflow-category= (=extras=);
- *edits* a near or shifted ledger amount to the bank's when its =item= names the payee;
- *reports* a salary deposit (=fin-conv-salary-regexps=) that differs from =bp= − =cnpj=: the tax booked is a fact the bank cannot tell.  Net rules (=fin-reconcile-net-rules=) fold only item-less =cnpj= rows; a =cnpj= row with an item was paid on its own.

Future-dated rows are skipped on both sides: ledger plan placeholders, and installments an open card bill lists before they are charged.

** Personal settings

=infra/config.el= (gitignored, loaded by =core.el= when present) holds what identifies you: =fin-bank-own-regexps= (own name, own company), =fin-conv-salary-regexps=, and =fin-conv-aliases= — payee words mapped to ledger item words (=("veronica" . "aluguel")=).

** Encoding

Nubank card bills declare =CHARSET:1252= but are UTF-8.  The parser ignores the header: valid UTF-8 decodes as UTF-8, anything else as windows-1252.

* Dashboard

=M-x fin-dashboard= writes =view/dashboard.html= and opens it.  Static, no JS.  Plain terminal look (monospace, lowercase labels, =$= prompt, aqua accent; no panel headings, the status bar names the current one).  One panel at a time, at most 640px wide and centered, picked from a tmux-like status bar at the bottom (=1:obj 2:cash 3:patr 4:acct 5:stat=, current marked =*=); each is a =#id= anchor shown with CSS =:target= (objectives when none), so the URL keeps the view and each number is also its =accesskey=; dark by default, light with =data-theme="light"= on =<html>=: every color is a theme role in =fin-dashboard--palette= (light and dark value), emitted as CSS custom properties and referenced as =var(--role)= in markup and SVG.  Values follow a validated data-viz palette with the financial convention: green for in / positive / on target, red for out / negative / off target (direction and position also encode it: above vs below the baseline, signed gaps), a neutral graphite accent, a fixed categorical order for shares without green or red (past six slices a neutral "other").  Hover text comes from SVG =<title>=.

A two-stat *hero* tops the page: /Final balance (entries)/ (latest cumulative net worth, Σ in − out) and /Accounts balance (now)/ (patrimony total); each colored pos/neg.

Under the header, on every panel, a full-width LED ticker of the records (net worth, best/worst month, biggest income/purchase, best/avg yearly save, recurring share, since, months); its tape keeps the content width.  CSS-only scrolling, dark in both themes, pauses on hover, static under reduced motion.

Five panels:
- *Stats*: the all-time flow bar chart and, stacked, the line trends (net worth, rolling save %, income-vs-expense MA, Pareto, yearly save %, spend heatmap), the share donuts (category, income) and the recurring tables (by months, all time).
- *Objectives*: KPI tiles (monthly liquid and unallocated share, fixed share vs its 55% target, runway, rows over target this month), then one bullet row per plan row and per child of =investments= (=domain/goals.el=): the bar's full width is the monthly target and the current month so far fills it green; spending past the target grows red from the right end by the overrun's share of the target (saving rows, =investments=, =retirement=, =emergency=, never turn red).  Actuals: same-named entry category; =investments= = everything it funds (its contributions minus =reserve= withdrawals, plus =family=, =vacations=, =patrimony= and =car= spending); =emergency= = =investments/emergency= minus =reserve=; =patrimony= = =patrimony= + =car= spending against the amortization.  Under it, one row per register class against its own monthly amortization: =car= entries are class =car=; =patrimony= entries take the class =fin-goals-patrimony-classes= (in =infra/config.el=, item regexp → class) maps their item to, and an =unmapped= row (target 0, so red) reports items the map doesn't cover yet.
- *Accounts*: balances + sub-accounts (expandable).
- *Patrimony*: items + amortization (expandable).
- *Cashflow* (right, tall): year → month → category → leaf (=item= · =date= · =amount=) drilldown.  Future months in the current year use plan-derived placeholders (dimmed).  The current-year header row reconciles with its months by summing actuals + forecast (in / out / liquid / save %).

Stats charts:
- /Net worth/ — cumulative Σ(in − out) per month.
- /Rolling save %/ — trailing 12-month save rate.
- /Income vs expense (12mo MA)/ — smoothed in / out lines, reveals lifestyle creep.
- /Pareto/ — top items by spend with cumulative %.
- /Spend heatmap/ — year × month intensity (log-scaled).
- /Yearly save %/ — discrete bars per year.
- /Category share/, /Income share/ — donuts.

* Testing

ERT-based, stdlib only.  Mirrors source layout under =tests/=.  Run:

#+begin_src sh
make test           # batch, exit code = pass/fail
make test-verbose   # full trace on failures
#+end_src

Or directly:

#+begin_src sh
emacs -Q -batch \
  -L . -L adapters -L domain -L tools -L view -L tests \
  -l tests/all-tests.el \
  -f ert-run-tests-batch-and-exit
#+end_src

Coverage scope:
- Pure formatters (=view/fmt.el=): every fn × edge (nil, 0, neg, k-suffix).
- Bank: OFX parsing (closed and bare SGML, cents without floats, encoding detection, statement period), inbox naming and re-export removal, idempotent import, matching buckets (exact, near, shifted, net, ignored), conventions (refunds, IOF, discounts, Pix via card, combined rows, savings nets, salary reports), ODS writer (row identity, date order, fail-loud on ambiguity, re-zip round trip, backup), review buffer and TSV export.
- ODS parser: cell-value precedence (=date-value= > =value= > text), =number-columns-repeated= expansion + cap.
- DB layer: schema rebuild idempotency, cents-as-integer storage, composite PK semantics.
- Domain queries: each public fn against seeded fixtures, including =/0=, =NULL=, future-month, multi-year scenarios.
- SVG charts: every renderer is empty-safe and emits expected structural tags.
- Dashboard integration: full render parses as HTML via =libxml-parse-html-region= on empty + seeded DBs.

Fixtures live in =tests/helpers.el= (=fin-test-with-db= macro, seed inserters, =fin-test-seed-minimal/multi-year/budget-tree= presets).  No external files needed; sync test stubs =fin-ods-parse= with an in-memory DOM.

* Decisions

- *ODS is canonical*, SQLite is a rebuildable mirror.  Edit in LibreOffice; refresh syncs.
- *Cents storage*: all money fields are integers (BRL × 100); float drift eliminated for SUMs.
- *Derived columns over stored*: share % for accounts/budget, monthly amortization for patrimony, fix-monthly for runway, investments amortization, future cashflow placeholders — all computed at query time.
- *Zero external runtime deps*: Emacs 29 stdlib (=sqlite=, =libxml=, =dom=) + macOS =unzip= / =zip=.
- *Static HTML dashboard*: no server, no JS, no port.  =M-x fin= opens the latest.
- *BRL only*: no currency column; every amount is BRL cents.
- =infra/finances.db= gitignored; ODS tables regeneratable from the ODS, bank tables from =infra/inbox/= (=fin-db-rebuild= leaves them alone).
- *Bank fixes the ODS, the ODS stays canonical*: =fin-bank-fix= edits =content.xml= as text so untouched rows stay byte-identical, keeps a backup, never touches the DB; =fin= then mirrors the fixed ODS.  It re-zips with =zip(1)=, the counterpart of the =unzip(1)= the reader uses.
- *Tests are stdlib*: ERT only, no =buttercup= / =undercover= / external runners.  Keeps the zero-deps invariant honest.
