#+TITLE: finances
#+OPTIONS: toc:nil num:nil

Personal finance tool in Emacs Lisp.  An ODS spreadsheet is the source of truth, SQLite mirrors it, and a static HTML dashboard reports on it.  Needs Emacs 29+ (built with SQLite) and =unzip= / =zip=; no other dependencies.

Scope: amounts are BRL; banks are any that export OFX, their statement wording read from a profile in =banks/=; the imposto de renda and obligations module covers a Brazilian Empresário Individual on the Simples Nacional paying a pró-labore, and shows only when configured.

* Setup

1. =cp examples/seeds.ods infra/seeds.ods=, fill the plan sheet.
2. =cp examples/config.el infra/config.el=, set your name, bank and accounts (see /Settings/).
3. Put each bank's OFX statements in =infra/inbox/<bank>/=.
4. =M-x fin= or =finances fin=.  The DB is created on first use.

Emacs: add =(load "/path/to/finances/bootstrap.el")= to =init.el=.

CLI: =make install= links =~/.local/bin/finances= (=PREFIX= to change); =make uninstall= removes it.  =finances <command>= runs any command in batch; =finances --shell= opens a REPL with the code loaded.

| Command                 | Action                                     |
|-------------------------+--------------------------------------------|
| =fin=                   | Reload, import, bank fix, sync, dashboard. |
| =fin-dashboard=         | Regenerate and open the dashboard.         |
| =fin-sync-refresh=      | ODS → DB.                                  |
| =fin-db-rebuild=        | Drop and recreate the ledger tables.       |
| =fin-open-ods=          | Open the ODS.                              |
| =fin-reload=            | Reload sources and config.                 |
| =fin-bank-import=       | Import new OFX statements.                 |
| =fin-bank-fix=          | Fix the ODS from the bank (=C-u=: dry run). |
| =fin-bank-reconcile=    | Read-only bank vs ledger review of a year. |
| =fin-bank-copy-missing= | Copy a year's bank-only rows as TSV.       |

* Monthly flow

1. Export the OFX statements into =infra/inbox/<bank>/=.
2. Close the ODS in LibreOffice (=fin-bank-fix= refuses while its lock file exists).
3. =M-x fin=: import, bank fix, sync, dashboard.
4. Read /Needs a look/ in the fix report when it shows.
5. Add rows paid outside the imported banks by hand, with =via= set (e.g. =cash=).

* Inbox

=infra/inbox/= keeps every source document (gitignored).  Names: =<source>-<cpf|cnpj>-<period>[-<kind>][-<id>].<ext>=, lowercase ASCII, ISO periods, ranges as =start_end=; yearly documents carry the ano-calendário.  Bank folders keep the names =fin-bank-import= gives.

| Folder             | What                                  | When        |
|--------------------+---------------------------------------+-------------|
| =<bank>/=          | account, card, PJ OFX                 | monthly     |
| =ir/pgdasd/=       | PGDAS-D declarations, DAS statements  | monthly     |
| =ir/=              | Receita payments, DCTFWeb, guides     | monthly     |
| =ir/defis/=        | DEFIS                                 | yearly      |
| =ir/dirpf/=        | return, receipt, original file        | yearly      |
| =ir/caixa-postal/= | e-CAC messages, compliance notices    | when notified |
| =ir/<accountant>/= | accountant invoices and reports       | monthly     |
| =nfse/=            | invoices issued, index CSV            | monthly     |
| =inss/=            | CNIS                                  | yearly      |
| =docs/=            | company registration papers           | on change   |

Keep digital certificates (=.pfx=) out of the inbox; the cockpit to do flags key files left there.

* ODS sheets

Category and name values are lowercase kebab-case; money is integer cents.  =examples/seeds.ods= is the empty template.

- =entries=: =date | type | category | item | amount | installment | installments | via=
  - =type= is =in= or =out=; every row is a leaf.
  - =installment= / =installments=: /k/ of /n/, one row per installment, else both empty.
  - Company tax is an =out= row under =cnpj=.
  - Savings moves (=fin-report-transfer-categories=) are neither income nor spending.
- =plan=: =category | parent | type | amount | share=
  - =type= is =income=, =fix= or =var=.  =income= rows =brute= and =cnpj= set the liquid base; without them it is the actual monthly average.
  - =fix= rows are driven by =amount=, =var= rows by =share= of liquid; children may use either.
  - =investments= children: a patrimony amortization row, then share-driven rows splitting what remains (may be negative).
- =patrimony=: =category | item | amount | lifespan_months=; monthly amortization = amount / lifespan.

Liquid = average monthly income less =cnpj= tax; future months forecast from the plan.
Accounts are not a sheet: =fin-accounts-derived= rebuilds each balance from the statements (=:into= / =:out-of= regexps from =:opening= on =:since=, or =:balance= of a statement), with =:yield=, =:closed= and =:reserve= (counts toward runway).  Net worth is their total.

* Bank

- *Import*: =fin-bank-import= reads any bank folder under =infra/inbox/=, renames files to =<bank>-<kind>-<start>_<end>.ofx=, replaces re-exports and dedups rows into the DB.  Bank tables survive =fin-db-rebuild=.
- *Profiles*: =banks/<bank>.el= holds a bank's statement wording (installments, refunds, fees, savings moves, bill payments); load it from =infra/config.el=, as =examples/config.el= does with =banks/nubank.el=.  Without a profile those folds are off.
- *Fix*: =fin-bank-fix= compares bank rows since =fin-bank-fix-from= (default: first day of last month) with the ledger and writes the fixes into the ODS.  Running it again changes nothing.
  - folds refunds, fees and pass-through payments into their purchases;
  - ignores card bill payments, own transfers and savings moves;
  - matches rows exact, near, shifted or combined;
  - adds bank-only outflows under the payee's usual category, inflows from people under =extras=;
  - edits near amounts when the ledger item names the payee;
  - reports what it cannot settle (salary gaps, refunds with no purchase) under /Needs a look/.
  Rules: =domain/conventions.el=, =domain/reconcile.el=, =tools/bankfix.el=.

* Dashboard

=M-x fin-dashboard= writes =view/dashboard.html=: one panel at a time, picked from a status bar (=1:cockpit 2:wealth 3:spending 4:ir=, each number its =accesskey=).  Dates read =dd/mm/yyyy=, months =mm/yyyy= or by name; amounts =1,234.56=, =R$= only in tiles and sentences.  Dark by default, light with =data-theme="light"=; colors are roles in =fin-dashboard--palette=.

- *Cockpit*: tiles (this month's balance with in / out / saved, savings, runway), All time flow, Fixed and Variable goals, To do (=tools/health.el=: ledger vs bank, IR risks, inbox, manual items).
- *Wealth*: Income vs expense, Yearly (year → month → category → item), Rolling save %, Net worth, Accounts, Patrimony.
- *Spending*: Records, Pareto, Heatmap, Category share, Income share, Recurring monthly, Recurring by count.
- *IR* (only when configured): tiles, Yearly (expands to months), Rules, Inputs.  Risks go to the cockpit to do; obligations come from =domain/duties.el=.
- Empty ledger: the to do says how to start, the other panels wait.

* Design

- Static HTML, no JS, no server.
- Money is BRL integer cents.
- The ODS is canonical: =fin-bank-fix= edits =content.xml= as text, untouched rows stay byte-identical, and re-zips with =zip=.
- =infra/finances.db= is regeneratable: ledger tables from the ODS, bank tables from the inbox.
- Tests are ERT only.
